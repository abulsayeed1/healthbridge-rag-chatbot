# Report 04: Hybrid Retrieval and Vector Storage

## 1. Vector Database Implementation (Harsha)
To store the 1,013 optimized chunks generated in Stage 3, we implemented a persistent local Vector Database using **ChromaDB** (`src/ragbot/store/vectorstore.py`). 

Before insertion, every chunk was passed through the open-source `BAAI/bge-base-en-v1.5` dense embedding model. This converted the text into 768-dimensional vectors. We selected ChromaDB because it runs entirely locally, ensuring that no sensitive hospital data is ever transmitted to a cloud vector database. The deterministic MD5 chunk IDs generated by the architecture tier were used as primary keys in ChromaDB, enabling idempotent upserts and preventing duplicate entries during subsequent data scrapes.
